# Visual Alpha industrial assets

Six original, deterministic GLB 2.0 models used by the LK Design System 3D
Visual Alpha Storybook. They are composed from real indexed triangle meshes,
normals, named nodes, and PBR materials; none of the files is an empty test
fixture.

| Stable file            | Model                    | Approximate core-space size (m) |
| ---------------------- | ------------------------ | ------------------------------- |
| `amr.glb`              | Differential-drive AMR   | 1.213 × 0.830 × 0.687           |
| `rack.glb`             | Three-level storage rack | 1.043 × 2.440 × 2.438           |
| `pallet.glb`           | Euro-style pallet        | 1.200 × 0.840 × 0.220           |
| `cargo-bin.glb`        | Stackable cargo tote     | 0.940 × 0.740 × 0.700           |
| `charging-station.glb` | AMR charging dock        | 0.873 × 0.820 × 1.360           |
| `safety-cone.glb`      | Warehouse safety cone    | 0.500 × 0.500 × 0.785           |

## Coordinate and origin contract

- right-handed coordinates
- `+Z` up
- `+X` forward
- one unit equals one meter
- each model rests on the `z = 0` floor plane
- the file-to-LK-core transform is identity

This is deliberately the LK core convention, not glTF's conventional `+Y`
authoring orientation. A Three.js scene that uses these files should set its
world/camera convention to `+Z` up and must not apply an additional Y-up to
Z-up normalization.

## Catalog and manifests

[`catalog.json`](./catalog.json) is the Storybook-facing collection. Every
entry exposes a stable relative `file`, a strict manifest path, coordinate
metadata, bounds, SHA-256 integrity, source, license, and provenance.

[`manifests`](./manifests) contains one strict `AssetManifestV1` document per
GLB. Provenance and license live in the collection catalog because the strict
V1 package schema rejects extension properties.

When this directory is mounted as Storybook static directory `/visual-alpha`,
the public model URLs are:

```text
/visual-alpha/amr.glb
/visual-alpha/rack.glb
/visual-alpha/pallet.glb
/visual-alpha/cargo-bin.glb
/visual-alpha/charging-station.glb
/visual-alpha/safety-cone.glb
```

Relative paths in `catalog.json` also allow the whole directory to be served
under a different base path without rewriting the catalog.

## Reproduce and verify

From the repository root:

```powershell
node scripts/generate-visual-alpha-assets.mjs
```

The generator is dependency-free and deterministic. It regenerates the six
GLBs and manifests, then verifies each GLB header, version, total length,
JSON/BIN chunks, declared buffer size, mesh/node/accessor presence, persisted
SHA-256, and manifest checksum. Machine-readable results are written to
[`verification.json`](./verification.json).

To validate the strict manifests against the package implementation after the
assets package has been built:

```powershell
@'
import { readFile, readdir } from "node:fs/promises";
import { parseAssetManifest } from "./packages/assets/dist/index.js";
const dir = "./packages/assets/visual-alpha/manifests";
for (const file of await readdir(dir)) {
  const value = JSON.parse(await readFile(`${dir}/${file}`, "utf8"));
  const result = parseAssetManifest(value);
  if (!result.ok) throw new Error(`${file}: ${JSON.stringify(result.issues)}`);
}
console.log("All Visual Alpha manifests are valid.");
'@ | node --input-type=module
```
