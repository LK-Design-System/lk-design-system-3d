## 확정한 제품 방향

맵 저작은 한쪽만 택하지 않고 다음 두 진입 경로를 함께 지원한다.

1. 브라우저의 Native 2.5D Builder에서 level, floor, wall, door, route graph, area,
   goal, charger/dock과 asset을 직접 만든다.
2. Unity, Unreal 또는 Isaac Sim/OpenUSD에서 만든 장면을 가져와 좌표와 의미를
   정규화하고, web-authored semantic overlay를 보존하며 제한적으로 재가져오기와
   내보내기를 지원한다.

두 경로는 renderer-neutral `LK Map Document`와 논리적 `LK Map Bundle`로 합류한다.
USD는 authored interchange의 우선 후보, GLB와 ROS occupancy는 파생 runtime output이다.
세부 결정, ownership과 단계는
[ADR-0002-DUAL-PATH-MAP-AUTHORING.md](ADR-0002-DUAL-PATH-MAP-AUTHORING.md)와
[IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)의 M5가 기준이다.

### 구현·UI 부채

- 현재 spatial authoring Story의 `MapEditorDocument V2`는 Story-local fixture이지
  production/public map schema가 아니다. A0 contract와 A1 unified model 이전에 public
  API로 승격하지 않는다.
- `LK Map Document/Bundle`, USD codec/import/export, durable source binding, reimport
  3-way diff는 아직 구현되어 있지 않다. 현재 core spatial structure도 box, cylinder,
  asset leaf까지만 제공하며 wall polyline, door/lift, charger/dock과 waypoint-edge graph는
  없다.
- 현재 route는 모든 segment에 opaque corridor plane을 표시하고 fixture wall은 독립
  box 반복이다. 목표 grammar는 centerline+vertices+direction이 기본이며 corridor는
  selection/validation 때만 반투명으로 표시하고, 하나의 polyline wall identity가 mesh를
  생성하는 방식이다.
- 현재 `CanvasEditorShell.layers`에 넣은 object `Tree`는 provisional composition debt다.
  Public LDS `Tree`는 controlled selection, lock/visibility, unmapped, diff/validation과
  row action 계약이 부족하다. LDS additive structure contract 또는 product-owned
  composition을 별도 승인하기 전 LDS3D custom hierarchy를 만들지 않는다.
- `SelectionInspector`는 selected entity만 소유한다. Active tool/draft, import mapping,
  calibration과 document validation을 fake selection으로 넣지 않는다.
- Unity/Unreal/Isaac adapter와 engine plugin은 아직 문서 방향이다. 현재 Storybook은
  engine file workflow, storage, permission, revision/merge 또는 배포를 구현한 제품이
  아니다.
- Transform gizmo의 concurrent numeric edit revision/session과 unmount/reparent 중 drag
  종료 의미는 아직 명시적 제한으로 남아 있다. TF/Marker/spatial cross-package golden
  fixture도 `testing` package가 아니라 각 package test에만 있다.
- LDS visual parity는 clean pinned LDS와 light/dark, wide/320/390, normal/error/disabled
  상태를 side-by-side로 다시 검토하기 전 주장하지 않는다.

## 금지선

- LDS3D renderer package에 LDS 또는 product dependency를 넣지 않는다.
- sibling LDS의 `src/`, story 또는 내부 CSS를 직접 import/copy하지 않는다.
- product file I/O, history, permission, storage, conflict apply 또는 deployment를 LDS3D가
  소유하지 않는다.
- GLB나 occupancy PNG/YAML을 authored source of truth로 취급하지 않는다.
- 이 checkpoint를 publish, registry release, production-ready 또는 visual-parity 증거로
  해석하지 않는다.
